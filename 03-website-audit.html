A22

Published test site: every page except the homepage returns 404

HighConfirmed issueNew Oct 5
Page/section
All subpages and posts on the published test site
File or URL
https://offshore-tng02.sakura.ne.jp/right-core/; .htaccess in the right-core folder; Settings › Permalinks
Finding
The homepage works, but /news/, /works/, /works/onekamakura/, every other post, and all planned page addresses return the server's own "Not Found" page. WordPress never runs for these addresses. The same content loads through WordPress with the plain form ?post_type=news, so the content exists; only the pretty addresses fail.
Evidence
HTTP 404 with the server's plain error page (not the theme) for every pretty address; HTTP 200 for /right-core/?post_type=news and ?post_type=works. The homepage links to 14 of these addresses. The sitemap address also returns 404 there (expected while search engines are discouraged).
Why it matters
Every News, Works and Instagram link on the test site is broken, so nothing beyond the homepage can be reviewed there. If the same server setup is used for launch, the live site would have the same problem.
Recommended action
  • In the test site's WordPress admin, open Settings › Permalinks and click Save. This rewrites .htaccess if WordPress can write to it.
  • If it cannot, upload the standard WordPress .htaccess to the right-core folder with RewriteBase /right-core/ and RewriteRule . /right-core/index.php [L].
  • Check that the FTP upload did not skip hidden files such as .htaccess.
How to verify
Open /right-core/news/ and one works post on the test site: the theme loads (not the plain server page) and the status is 200.
A1

News, Works and Instagram pages show only a placeholder

HighConfirmed issueNews built
Page/section
News list and posts, Works list and posts, Instagram list and posts, default post and page
File or URL
/news/, /works/, /instagram/, /works/sushi-okazaki/ and every other single post, /hello-world/, /sample-page/. Theme has only index.php as fallback (no archive-*.php or single-*.php).
Finding
These URLs return HTTP 200 but show only an H1 「RIGHTCORE」 and the text 「トップページをご覧ください」. The real post content is never displayed.
Evidence
Page source of /works/sushi-okazaki/: title 「Sushi Okazaki – rc_renewal_project」, H1 「RIGHTCORE」. The homepage links to these pages from Works cards, News items, Instagram cards and the 「すべて見る」 buttons, and all of them are listed in /wp-sitemap.xml.
Why it matters
Google finds many near-empty pages with the same text, which it can treat as low-value or as "soft 404" pages. Visitors who click a work or news item see nothing useful. This is the most important problem found.
Recommended action
  • News: build archive-news.php and single-news.php.
  • Works: build archive-works.php and single-works.php.
  • Instagram: an Instagram feed plugin will replace the temporary post type soon (see SNS in the site map). Until then, keep its pages out of the sitemap and search; do not build templates for it.
Progress (Oct 5)
News list and detail templates are built in development (see News in the site map); not yet uploaded. Works and Instagram are still open. On the test site, ?post_type=news and ?post_type=works still show the placeholder.
How to verify
Open each list and single URL: the H1 is the real post or list title, the content appears, and the page title is unique. Search the page source for 「トップページをご覧ください」; it should not appear on any of these pages.
A2

Site name is a placeholder in every page title

HighConfirmed in developmentFixed on test site
Page/section
All pages
File or URL
WordPress Settings › General › Site Title. Titles are printed by wp_head() through add_theme_support('title-tag') in functions.php.
Finding
The homepage title is only 「rc_renewal_project」, and other pages end with 「– rc_renewal_project」.
Evidence

Changing Settings › General › Site Title now updates the page title and the name on the page together. The development build still has the placeholder Site Title, so it shows 「rc_renewal_project」 in those places until the setting is changed.
How to verify
Page source of /, /about/, a news post and a works post shows the approved, unique titles.
A3

Broken links and placeholder links

HighConfirmed issue
Page/section
Header, About, Services, Recruit, FAQ, Footer
File or URL
header.php, footer.php, template-parts/sec-about.php, sec-service.php, sec-recruit.php, sec-faq.php
Finding
  • /faq/ returns 404 (FAQ button, sec-faq.php line 75).
  • /privacy-policy/ returns 404 (footer, footer.php line 139).
  • #company has no matching section on any page (header.php line 270, footer.php line 132).
  • #services does not exist; the section id is service (footer.php line 131).
  • On /about/, menu links such as #works and #faq point to sections that only exist on the homepage.
  • 14 links on the homepage use href="#": もっと見る buttons in About (sec-about.php 58), Services (sec-service.php 22, 175) and Recruit (sec-recruit.php 28); service card links (sec-service.php 56, 92, 128, 164, and an empty href="" at line 44); Facebook and X icons (footer.php 106, 115).
Evidence
HTTP status checks, and a scan of every <a> in the homepage and /about/ HTML.
Why it matters
Google discovers pages by following real links with an href address. Dead links also waste visitors' clicks and look unfinished.
Recommended action
Point every link to its page address, even before the page is built: menu items, contact buttons, もっと見る buttons and service cards. They return 404 only until each page in the page plan is published. Use dummy addresses for Facebook and X until the official accounts are confirmed. Never leave # or an empty href.
Progress (Oct 5)
Done in development (C2, C3):
  • Header, mobile menu and footer site map link to /about/, /service/, /company/, /works/, /recruit/, /faq/ and the News list. Contact buttons link to /contact/.
  • もっと見る buttons link to /about/, /service/ and /recruit/. Service cards link to /service/#creative, #design, #media and #global.
  • Facebook and X use dummy addresses (https://www.facebook.com/, https://x.com/) until the accounts are confirmed.
  • The homepage has no href="#" or empty links left.
Expected for now: About, News and Works open; the other addresses are 404 until their pages are built (section 2). The test site still has the old links until the theme is uploaded.
How to verify
Run a link checker (for example a site crawler) on staging: no 404s and no # links. Click every menu item from both / and /about/.

A5

No meta descriptions

MediumConfirmed issue
Page/section
All pages
File or URL
header.php (wp_head()); Yoast SEO now installed
Finding
No page has a <meta name="description">.
Evidence
Checked /, /about/, /news/, /works/ and the search page: 0 description tags.
Why it matters
Google may use the description as the text under the link. Without one, Google picks text from the page itself. It does not change rankings, but a good summary can help people choose our result.
Recommended action
Set all metadata in Yoast SEO, in WordPress admin. Do not also add it in the theme, or pages will show two descriptions. Coders write a unique description for each page, starting with the homepage, About, News list and Works list.
How to verify
Page source shows exactly one description per page, with the approved text.
A6

Homepage is very heavy on phones

HighConfirmed issue
Page/section
Homepage, mainly MV, Recruit, Works, Footer/Contact, and site-wide fonts
File or URL
assets/css/fonts/NotoSans.ttf, assets/img/top/mv01–04.jpg, footer/cta-bg.jpg, top/header_mv.jpg, top/sec04-bg.png, uploaded Works images
Finding
One homepage visit downloads about 27.4 MB in 66 requests.
Evidence
  • NotoSans.ttf font: 8.9 MB
  • MV photos mv01–mv04.jpg: 1.4–2.4 MB each
  • cta-bg.jpg 1.6 MB, header_mv.jpg 1.4 MB, sec04-bg.png 1.2 MB
  • Four uploaded Works images named ChatGPT-Image-…-1024x889.png: 0.95–1.3 MB each
  • Only 19 of 42 images have width and height attributes
  • The largest item on screen (LCP) is mv02.jpg; layout shift (CLS) measured 0.000
Why it matters
Phones on mobile data load this slowly. Google includes loading experience (Core Web Vitals) in page experience, and slow pages lose visitors before they contact us.
Recommended action
  • Replace the 8.9 MB TTF with a subset WOFF2 file or Google Fonts' Noto Sans JP with display=swap.
  • Resize photos to about twice their largest displayed size and export as WebP or compressed JPEG. Aim for under about 300 KB each (see Suggested image sizes).
  • Keep the first MV image loading immediately and add fetchpriority="high"; keep loading="lazy" on images further down.
  • Add width and height to every <img>.
  • Resize the Works images ourselves and output them with WordPress image sizes (srcset).
How to verify
DevTools › Network with cache disabled: record total transferred size before and after. PageSpeed Insights (mobile) on the staging or live URL: save the report before and after.

A9

Indexing settings: staging must stay hidden, production must stay open

HighDevelopment verifiedTest site hiddenProduction needs verification
Page/section
Site-wide
File or URL
Settings › Reading › Search engine visibility; /robots.txt
Finding
In the development build, pages have no noindex, robots.txt allows crawling and lists the sitemap, and the search results page correctly has noindex, follow. The published test site (offshore-tng02.sakura.ne.jp/right-core) has noindex, nofollow on its homepage, so it is hidden from Google as it should be. Its domain /robots.txt allows everything, which is fine because noindex is what hides the pages. Production could not be checked.
Evidence
Homepage: <meta name='robots' content='max-image-preview:large'>. Search page: noindex, follow. robots.txt: Disallow: /wp-admin/ and the sitemap line.
Why it matters
If staging is indexed, Google may show the test copy instead of the real site. If production accidentally has noindex, the real site disappears from Google.
Recommended action
Staging: turn on "Discourage search engines" and, ideally, protect it with a password. Production: confirm it is not discouraged. Remember that robots.txt alone does not keep a page out of Google.
How to verify
Screenshots of the Reading setting on each server, page source of each homepage, and each /robots.txt. After launch: Search Console › Pages report.

MediumHomepage missingProduction needs verification

File or URL

Finding
/about/ and single posts output a canonical tag; the homepage does not. On the published test site, http:// loads the page directly (status 200) instead of redirecting to https://. That is acceptable for a hidden test copy, but production must redirect. Production redirects could not be checked.

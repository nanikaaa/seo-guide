5.2 WordPress checklist & plugins

Our current 23-item checklist (Coder / Seira) makes a site that works. This page adds what it needs for search: SEO notes on the existing items, new SEO checks 24–50, the plugins to add, and how to set them up. Use it on RightCore and on every future WordPress site.

What plugins can and cannot do

Plugins fix the technical side: Google can find, read and load every page quickly. Ranking itself comes from useful pages (services, real Works, News), the Google Business Profile for map results, and other sites linking to us. A site with every plugin installed and empty pages will not rank.

Add

Plugin
EWWW Image Optimizer Add
Why
Compresses images when they are uploaded, resizes very large uploads, and can serve WebP. Our audit found 1–2.4 MB photos; staff uploading News and Works images will keep adding them without this.
Settings
Resize images: max 2560 × 2560. Remove metadata: on. WebP conversion: on (test that images still show after enabling). Run "Bulk Optimize" once for existing uploads.
Alternative
Converter for Media (WebP only). Do not use two image plugins together.
Plugin
Redirection Add
Why
Creates 301 redirects from the admin when an address changes, and logs 404s so we can see broken links visitors actually hit. Needed when the temporary /instagram/ posts are replaced by the feed plugin.
Settings
Monitor permalink changes: on. 404 log: keep 1 month. Check the 404 log monthly.
Note
Yoast SEO Premium includes a redirect manager; with the free version, use Redirection.
Plugin
Site Kit by Google Add at launch
Why
Connects Search Console and Google Analytics 4 in one step and shows their numbers in the dashboard. Easiest way for the team to see search traffic.
Settings
Connect Search Console and Analytics with the company Google account (not a personal one). Do not add the GA4 tag again in the theme.
Alternative
Verify Search Console in Yoast › Site connections and add GA4 by hand. Either way, only once.
Plugin
Cache plugin: WP Fastest Cache Only if the host has no cache
Why
Serves saved HTML instead of building each page in PHP, so the server responds faster.
First check
Many Japanese hosts have a server-side cache in the control panel (for example Sakura's コンテンツキャッシュ, Xserver's サーバーキャッシュ). If it is on, do not add a cache plugin. If the server runs LiteSpeed, use LiteSpeed Cache instead.
Settings
Cache system: on. Minify HTML/CSS: on. Combine JS: test carefully (can break sliders). Clear the cache after every deploy.
Plugin
Regenerate Thumbnails Temporary
Why
Creates new image sizes for old uploads after we add add_image_size() (C8). Run once, then delete.
Plugin
Instagram feed Decision pending
Why
Planned for the SNS area (section 2). Choose one that loads images lazily and does not add the feed's posts as pages on our site.

4. Yoast SEO settings

The project uses Yoast SEO. Keep it as the only SEO plugin. Menu names below are from Yoast SEO › Settings; they can move slightly between versions. Make the settings on development first, screenshot each screen for the evidence folder, then repeat on production after approval.

Install Yoast everywhere we test. It is on the development and production servers, but not in the Local copy (rcrenewalproject) or on the published test site. Install the same version there so the theme is tested with Yoast's real output.

Advanced › Date archivesEnable date archivesOff.
Advanced › Media pagesEnable media pagesOff (attachment addresses go to the file itself).
Advanced › Special pagesSearch page and 404 titlesJapanese: 「「%%searchphrase%%」の検索結果 %%sep%% %%sitename%%」, 「ページが見つかりません %%sep%% %%sitename%%」. Yoast already sets search results to noindex.
Advanced › BreadcrumbsEnable breadcrumbs for your themeOn. Home anchor text 「トップ」. Then add yoast_breadcrumb() to the theme (section 5).

In each page and post (Yoast box under the editor)

  • SEO tab: SEO title, slug (short English), meta description. Write them; do not leave the template default on important pages.
  • Advanced tab › 「Allow search engines to show this content in search results?」: No on contact0-check and contact0-finish. Noindex pages are left out of the sitemap automatically.
  • Social tab: share image when a page needs a different one from the site image.
  • The traffic lights (SEO and readability analysis) are designed around English and are only a guide on a Japanese site. Never repeat keywords to make them green.

Check after setting

  • Page source: one <title>, one name="description", one rel="canonical", one yoast-schema-graph script.
  • /sitemap_index.xml lists pages, news and works only; /wp-sitemap.xml redirects to it.
  • Rich Results Test on the homepage and one news post: Organization and BreadcrumbList with no errors.

5. Code for checklist items

Breadcrumbs with Yoast (item 4)

Yoast already includes BreadcrumbList in its structured data on every page, even before breadcrumbs are shown. Do not add our own breadcrumb JSON-LD, or Google sees two. Turn on Advanced › Breadcrumbs, then print the visible breadcrumb with Yoast's function.

Fixed header without layout shift (item 11)

When the header changes from normal to fixed, the content below jumps up by the header's height. Fix the header from the start and reserve its height, or keep a placeholder of the same height.

wp-content/uploads/.htaccess (item 20)

Load reCAPTCHA only on the contact pages (item 16)

Optional. Google recommends loading reCAPTCHA v3 on every page for better bot detection, but it is a large script and lowers the mobile speed score of every page. For a small company site, the contact pages are enough.

SNS list and SNS detail (Instagram)

Plugin plannedTemporary post type
Plan
The SNS (Instagram) area will move to an Instagram feed plugin soon. The plugin is not chosen or approved yet. Until then, the temporary post type instagram stands in, with a list at /instagram/ and detail pages at /instagram/{slug}/.
What we understand now
  • How a feed plugin works: it pulls posts from the connected Instagram account and shows them on our page. The posts stay on Instagram; we do not copy them into WordPress. Clicking a post usually opens Instagram or a popup, so there is normally no detail page on our site.
  • Detail pages will go away: the current /instagram/{slug}/ pages are temporary. Any that have been public must redirect (301) to the SNS list or the homepage SNS section when the plugin goes live, or visitors and Google get 404s.
  • Search value: the feed is Instagram's content, not ours, so treat SNS as a feature for visitors, not as SEO content. Keep the temporary pages out of the sitemap and out of Google (noindex) until the switch.
  • Account connection: Meta shut down the Instagram Basic Display API on December 4, 2024. Feed plugins now connect through Meta's newer Instagram API, and most plugin guides say the account must be a Professional (Business or Creator) account. We must confirm this with the plugin we choose, and confirm which account is official (A14 lists 「rightcore_manila」).
  • Keeping it running: if the connection breaks (for example a password change or removed permission), the feed stops updating. One person must own the Instagram login and reconnect the plugin when needed.
  • Speed: feed images load from Instagram's servers and the plugin adds its own scripts and styles. Check the page weight before and after (A6), and use lazy loading if the plugin offers it.
  • Privacy: the Privacy Policy should mention that the site shows embedded content from Instagram (Meta).
  • Design: the current SNS design must be rebuilt around what the plugin can output. Check its layout and styling options before choosing.
To decide
  • Which plugin (free or paid), and when it goes live.
  • Which Instagram account, and who owns its login.
  • Where the feed appears: homepage section only, or also its own page. If its own page, use /sns/ or /instagram/.
  • When to remove the temporary post type, and the redirect list for its pages.
  • Clean up the duplicate posts if the post type stays until launch: 「スタッフインタビュー」 on the test site and 「新しいコーポレートサイトが公開されました」 in development (one slug ends in -2 in each).
Sources
Smash Balloon: Instagram Basic Display API shut down · Spotlight: The end of Instagram Basic Display API

Shared rules for every new page

  • Short English slugs, decided before publishing. Changing a public address later needs a 301 redirect.
  • One H1 per page; unique title and description, written by coders and set in Yoast SEO (A2, A5).
  • Header and footer link to the real page once it exists, instead of a homepage anchor (A3).
  • Images sized and compressed as below, with width, height and alt text (A6, A7).
  • Pages in development stay off the live site until approved.

Suggested image sizes

Based on Google, web.dev and WordPress guidance. Pixel widths follow the "about twice the displayed size" rule in A6; file sizes are our own working targets, not Google rules.

Image Upload width Format Target file size
Full-width MV and page header photos 1920–2560px (WordPress scales anything wider than 2560px down) WebP or compressed JPEG Under about 300 KB
Photos inside a section (About, Recruit, Service) About twice the displayed width, usually 1200–1600px WebP or compressed JPEG Under about 200 KB
Cards and list images (Works, News) About 800px WebP or compressed JPEG Under about 100 KB
Logo and icons Vector SVG (PNG only if needed) As small as possible
Share image (Open Graph) 1200 × 630px JPEG or PNG Under about 300 KB
  • Upload through the Media Library and output images with WordPress functions. WordPress then creates smaller copies (150, 300, 768, 1024, 1536 and 2048px) and adds srcset so phones get a smaller file.
  • Every <img> has width and height. The first MV image loads immediately with fetchpriority="high"; images further down use loading="lazy".
  • Use short, descriptive English file names, for example office-osaka.jpg instead of IMG00023.jpg.

Alt text rules

  • Photo that carries meaning: a short, factual description in Japanese.
  • Image that contains text (for example a heading or company details drawn in the design): the alt repeats that text exactly. This uses the real information already in the design.
  • Image inside a link or button: the alt says where the link goes or what it does.
  • Decorative image (bullets, background shapes, an icon next to the same words): alt="".
  • No keyword lists in alt text. Google warns this can make a site look like spam.

Proposed order of work (for discussion)

  1. Step 0 — unblock the test site: fix the 404s on the published test site (A22) so pages can be reviewed there.
  2. Phase 1 — needed for launch: News (upload what is built), Works, Privacy Policy, Contact (with Privacy Policy live first), 404.
  3. Phase 2 — company pages: Company, Service, Recruit, FAQ, and final About content.
  4. Phase 3 — after approval: install the SNS feed plugin, remove the temporary post type, and add redirects for its pages.
